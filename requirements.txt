# Lets outgoing mail be verified against the OPERATING SYSTEM's certificate
# store instead of the one bundled inside Python.
#
# This is not cosmetic. Antivirus "mail shields" (Avast, ESET, Kaspersky) and
# campus proxies intercept SMTP over TLS and re-sign it with a CA they have
# added to the OS trust store. Windows accepts those certificates; Python's
# bundled verifier is stricter and rejects them, so on such a machine no
# verification email can leave at all - with an error that looks like a
# credentials problem but is not.
#
# Optional: services/email_service.py falls back to Python's own roots if this
# is not installed, and DIGISAFE_SYSTEM_TRUST=false refuses interception
# outright.
truststore>=0.9.0

# --- Machine Learning (Sections 3.3.6 / 3.12.3) ---
#
# These four are PINNED EXACTLY, unlike everything above, because the trained
# models in ml_model/*.joblib are pickles produced by these versions. joblib
# artefacts are not guaranteed to load across scikit-learn or numpy releases,
# so a floating ">=" here would let a future release silently break evidence
# classification on the next deploy.
#
# Pinning is what lets the deployment host simply install and run, instead of
# retraining to guarantee a version match. That matters on a 512 MB free-tier
# instance, where fitting the model during the build risks an out-of-memory
# failure. Retraining is still one command if the corpus changes:
#
#     python ml_model/build_dataset.py && python ml_model/train_model.py
#
# If you bump any pin below, retrain and re-commit the .joblib files together
# with the pin, in the same commit.

scipy==1.18.1
